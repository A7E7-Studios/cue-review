# Architecture

CueReview is a desktop application for recording a review, replaying its video alongside a local transcript, and handing selected evidence to an agent. Windows is the hardware-verified platform; macOS and Linux builds share the same code with platform capture backends. Tauri owns native operations; React owns presentation and playback. Recording data stays in local project/session folders. No account or hosted inference service is required.

## Responsibilities

| Component | Responsibility |
| --- | --- |
| React/WebView2 | Session navigation and search, source selection, playback, word seeking, transcript, takes, settings, window chrome |
| Tauri/Rust | Validate command arguments, own capture processes and devices, persist metadata, run local media/transcription jobs |
| Windows Graphics Capture | Capture a selected display or window through `windows-capture` |
| Cursor sampler (`cursor.rs`) | Record the pointer and its buttons beside Windows display/window captures |
| CPAL/WASAPI | Capture the selected microphone and optional system output loopback |
| scrcpy/ADB | Capture authorized Android devices, including compatible Quest devices |
| FFmpeg/ffprobe | Normalize and combine media, inspect duration, extract frames and clips |
| whisper.cpp | Transcribe local audio and produce timestamped token JSON |
| Agent CLI (`cli.rs`, `agent.rs`, `bin/cue.rs`) | Discover sessions and retrieve transcript, frame, clip, cursor and moment evidence |

The implementation uses one active recording at a time. Long operations must run outside the UI thread. Native errors must reach the interface with recovery details; dependency or hardware failures must never return demonstration data.

The window chrome is part of the web UI on Windows: the window has no native decorations, and `src/chrome/TitleBar.tsx` draws the title bar with the Minimize, Maximize/Restore and Close controls through `src/chrome/windowApi.ts`. macOS uses an overlay title bar with the native traffic lights; Linux keeps native decorations. The backend still refuses to close while recording or processing, whichever control asks. See [DESIGN.md](DESIGN.md).

## Capture and synchronization

Windows Graphics Capture is the native display/window path. FFmpeg `gdigrab` is not a substitute for universally supported system audio: DirectShow only exposes configured capture devices. WASAPI loopback reads the rendering endpoint without requiring Stereo Mix or a virtual audio driver.

FFmpeg process recordings flush output packets so the startup check can see encoded video without
waiting for buffered Matroska data. Startup rejects an exited process or output that remains below
the readiness threshold; scrcpy uses its decoded-frame signal independently of file buffering.

macOS distribution packages use one approved Developer ID team and the fixed app identifier,
so their normal Apple designated requirement remains compatible across updates. Packaging signs
bundled executables before the enclosing app, retains hardened runtime and verifies the final
signature. CI imports credentials only in the restricted signing environment and removes its
transient keychain after use. Signing configuration belongs in the [build instructions](../README.md#macos-signing).

The hardened macOS bundle signs with camera and audio-input entitlements from
`src-tauri/Entitlements.plist`. Its camera and microphone usage descriptions explain the requests;
the entitlements permit macOS to present them, and the person's Camera and Microphone privacy
grants still control access. The installer smoke check inspects the signed bundle for both
entitlements.

Microphone and system audio have independent clocks. Retain capture offsets against one session origin, preserve silence and discontinuities, and align streams when producing the playback file. A recording must remain in sync when the output device is silent for several seconds. Muting a microphone must write silence without collapsing the timeline.

`AudioWriter` (`capture.rs`) writes each track (`mic.wav`, `system.wav`) back to back as the device delivers it, as mono 32-bit float; placing a packet by its timestamp × the nominal rate would leave a short hole wherever the device runs slow, heard as crackle. The WASAPI capture timestamps split the packets into runs at every pause of more than 50 ms (a glitch, or loopback while nothing plays), give each run its start in the take, and measure the device's clock against the wall clock over the runs' own audio. At Stop, `finish` rewrites the track: each run resampled by that ratio with a 32-tap Blackman-windowed sinc (a 1024-phase table, streamed from the file) and placed at its start by the wall clock, silence before, between and after the runs, so the track is exactly the take's length and a gap cannot shift what follows. A ratio more than 5% from 1, or under a second of audio, is not trusted and counts as 1. While recording, gaps are written as wall-clock silence so live snapshots read the track roughly in place, before that correction.

Windows Graphics Capture may emit frames only when the image changes. Stopping must be independent of receiving another frame. Encoder finalization is required after normal stop, source closure, and capture errors. A final static interval must remain represented in the finished video's duration.

scrcpy records encoded device streams with device timestamps. Those timestamps preserve device audio/video alignment; they do not automatically synchronize a separately captured PC microphone. The implementation must account for device startup latency and document any remaining alignment limit. When the display turns between portrait and landscape, scrcpy restarts its encoder at the other size, and FFmpeg rebuilds a filter graph at a size change, restarting `setpts=PTS-STARTPTS` and `tpad`, which lost or misplaced every frame after it. So when a key-frame probe (`-skip_frame nokey`) finds more than one frame size, `finalize` first letterboxes every frame onto the first frame's size with stateless filters (`scale`, `pad`) and their timestamps passed through, then muxes that as usual; `capture-timing.json` records `frameSizes`. ADB authorization and a connected device are required. Quest compatibility must be checked on the actual headset rather than inferred from Android support.

Previews use a continuous MJPEG response over an ephemeral loopback listener with a random per-stream URL token. There is no screenshot polling or per-frame React state update. Windows capture pushes JPEG frames directly; device previews run the installed matching scrcpy server in video-only raw-stream mode on a unique ADB forward and decode H.264 with FFmpeg. Cameras use FFmpeg's platform input: DirectShow on Windows, AVFoundation on macOS and V4L2 on Linux. Only the latest frame is retained if the viewer falls behind. Preview resolution is bounded independently of recording resolution. Starting a recording keeps the existing preview stream except for AVFoundation sources and V4L2 cameras, whose previews are released before recording opens them. These sources show Preview paused during startup and recording; failed startup resumes the draft preview. Switching sources or entering review stops the preview's owned resources. Frontend start/stop operations are ordered, and stale stop IDs cannot terminate a newer stream. Source errors reach the UI through a Tauri channel. Meta/Oculus Quest virtual-camera filters are excluded from enumeration in favor of authorized USB devices.

The preview decoder's stderr is drained concurrently into an 8 KiB in-memory tail. Errors include
source-access guidance and a UTF-8-safe diagnostic excerpt of at most 1024 bytes; an access-related
line is preferred to generic FFmpeg summaries. Teardown kills and reaps the decoder before joining
both pipe readers. A stream with no connected viewer reports its 15-second timeout. The media stage
checks intrinsic image dimensions because multipart streams need not fire a load event; after ten
seconds without a drawable first frame, it reports a recoverable error and releases that stream.
Image callbacks carry their connection identity so obsolete views cannot fail a replacement stream.

Final playback encoding uses x264 veryfast CRF23, retaining capture resolution and frame rate. A successful encoder exit is followed by stream and duration validation; only a clean capture with verified output removes its owned native-video.mp4 or native-video.mkv intermediate. Capture/finalization failures retain the native video. Lossless audio and transcription evidence remain available for retry. A Windows capture without microphone or system audio still gets a silent audio track, so every take video plays the same way. This policy applies to new captures, without retroactive changes to existing recordings.

## Takes (Record more)

"Record more" continues a ready session as a new take (`src-tauri/src/takes.rs`, plan decision 10), recording whichever display, window or device the recording bar chose: `record_more(id, sourceId, microphoneId, systemAudio, muted)`.

**Layout.** Take 1 is the session folder itself, so every recording made before takes existed is a one-take session and needs no migration. Take N records into `sessions/<id>/takes/<N>/` with the same files a single recording has, its own `video.mp4` included: nothing is joined, normalized or re-encoded, so takes of different sources and sizes keep their videos as recorded. `session.json` lists the takes once there is a second one: `takes: [{index, offsetMs, durationMs, status, folder, sourceId?, microphoneId?, systemAudio}]`, where `sourceId` is absent when it is the session's. A legacy session's take 1 is synthesized from the session until Record more writes it out. Folders and video files are always derived from the take index, never from `folder` or other metadata, so a damaged `session.json` cannot redirect a reader or cleanup.

**Session format.** `session.json` carries `formatVersion`; absent means 1.

| Format | The take videos | Written by |
| --- | --- | --- |
| 1 | One video, `video.mp4`, from 0 for `durationMs`: a single take, or every take joined into it by an earlier CueReview | every session with one take, and sessions saved before takes kept their own videos |
| 2 | `videos: [{take, startMs, durationMs}]` in timeline order; the file is `video.mp4` for take 1 and `takes/<N>/video.mp4` after. A take on the timeline without an entry of its own plays inside the entry before it (takes joined in format 1) | a session once a take has a video of its own |

A reader of format 1 needs no migration. The first take with its own video upgrades a session: take 1's entry `{1, 0, offset}` (its `video.mp4` holds everything before, joined takes included), then the take's own, and `formatVersion: 2`. `durationMs` is the end of the last video. A reader that finds a format above 2 refuses the session ("saved by a newer CueReview"), so the store skips it when listing and leaves its file alone; an older CueReview reading format 2 plays only take 1, since downgrading is not supported. `takes::videos` and `takes::video_at` (the last video starting at or before a time, and the time inside it) are the one lookup the CLI and the cursor use; `src/app/media.ts` has the same for the player.

**Offsets.** A take starts where the session timeline ends: `durationMs` of a format-2 session, or the probed duration of `video.mp4` for a format-1 one. While recording, `get_recording_status` reports `takeIndex` and `takeOffsetMs`; `elapsedMs` stays relative to the take. Live transcription shifts its words by the offset, so live words land on the session timeline.

**Source identity.** A `window:HWND` or `monitor:N` id can name something else after a restart, so the first capture (the app's Record and `cue record`) stores `sourceIdentity` in `session.json`: `{kind:"window", title, process, class, pid, processCreatedMs}` (the process image name, the window class, and the owning process id and its creation time in ms since the Unix epoch from `GetProcessTimes`) or `{kind:"display", device, left, top, right, bottom}` (the GDI device name and the monitor bounds in physical pixels). Record more does not check it: the take records what the bar lists under that id now, which the reviewer sees before recording. macOS and Linux store none.

**Lifecycle.** A take's status runs `recording` → `finalizing` → `transcribing` → `ready` or `error`. A take is on the timeline exactly when it is `transcribing`, `ready` or `error`, so `error` always means "on the timeline, transcript missing". Stop probes the take's own `video.mp4` and places it on the timeline with its probed duration, then transcribes only that take, re-reading `session.json` under the session lock at each step; a capture error with a usable video leaves the take `error`, its transcript to Retry. A take whose capture produced no usable video, or that the app lost while recording, becomes `interrupted`: it is not on the timeline and its folder keeps whatever was captured. Stop returns once the video is placed; the session stays `processing` while the take is transcribed.

**Format-1 takes waiting to be joined.** An earlier CueReview joined each take into `video.mp4` after Stop, and a take could be left `swapping`. Startup recovery, and `cue transcribe` before it transcribes, upgrade such a take: when `video.mp4` already lasts as long as the takes before plus this take (within a third of the take, at most 150 ms), it plays inside take 1's video and `durationMs` becomes that length; otherwise it plays from its own `video.mp4`, which the join never removed; either way it becomes `error` for Retry. When neither has it, it is `interrupted`; while `video.mp4` cannot be read, it keeps waiting, since only that file tells a joined take from a lost one. Retry and `cue transcribe` upgrade it the same way inside their job (`takes::upgrade`), without settling the session. Once it is upgraded, its `swap.json`, `swap.log` and `normalized.mp4` and the `concat-t<N>.ffconcat` list are deleted; a take that keeps waiting keeps the files in its folder. Startup recovery, and the upgrade inside Retry or `cue transcribe`, delete stray `video.*.tmp.mp4` files and ffconcat lists in the session folder either way. `cue discard-take` is kept for scripts and refuses every take: "Takes keep their own videos now, so no take waits to be added."

**Transcription.** Only the new take is transcribed, from its own audio, and its segments are shifted by its offset and given `t{N}-` id prefixes before they replace that take's segments in `transcript.json`. `transcript.takes` lists one `{index, startMs, language?, languageDetected?}` mark per take on the timeline (none for a single take), each with the language its take was transcribed in ([the take's language](#local-transcription)); the UI draws "Take N · m:ss" dividers and scrubber ticks from it, and `cue transcript --segments` prints `── Take N · m:ss ──` lines. The marks are saved even when the take's transcription fails (for example, the model is missing), so its divider and tick appear before its words. Retry works on the unfinished takes (`transcribing`, `error`, and a format-1 `swapping` take, upgraded first), or every take on the timeline when none is unfinished. Record more is refused while any take is unfinished, and Copy for agent is disabled while recording.

**Recovery at startup.** `Store::recover_interrupted` repairs every session the app did not finish:

| State found | Single-take session | Take N of a multi-take session |
| --- | --- | --- |
| `recording`, `finalizing` | Session `error`, original media retained, Retry offered when video exists | Take `interrupted`, raw tracks kept in `takes/<N>/`, earlier takes intact. A `finalizing` take whose own `video.mp4` was finished and probes as valid goes on the timeline as `error` instead, so Retry transcribes it |
| `swapping` (format 1) | — | Upgraded: inside take 1's video or from its own, then `error`; `interrupted` when neither video has it (see above) |
| `transcribing` / `processing` | Session `error`, retained media, Retry | Take `error`, so Retry transcribes only that take |
| Stray `video.*.tmp.mp4`, `concat-t*.ffconcat` | — | Deleted |

A session then settles: `error` with a message naming the first unfinished take, or `ready`. A session whose `session.json` cannot be read or repaired is skipped and logged, so one damaged recording never keeps the app from starting. A skipped session that was still `recording` or `processing` is marked `error` with a message the app shows ("The app closed before this recording finished, and CueReview could not repair it when it started again: …"), so it offers Retry and Delete instead of looking busy forever. Listing sessions (the sidebar, `cue sessions`) likewise skips and logs a `session.json` that cannot be read, so a torn file never hides the rest of the library.

## Cursor tracking

On Windows, display and window recordings run a sampler thread beside the capture (`src-tauri/src/cursor.rs`), for the app and `cue record` alike. It starts once the first video frame has arrived and is stopped and joined first when the capture stops, so every sample lies inside the take. About 60 times a second it reads `GetCursorPos` and the left, right and middle buttons through `GetAsyncKeyState`, honoring swapped buttons; a press and release between two polls is still written. The thread is per-monitor-v2 DPI aware, so coordinates are physical pixels, like the captured frames.

**Clock.** Samples are timed on the capture epoch, which is also t=0 of the take's video, audio and transcript words. Adding the take's offset puts them on the session timeline.

**Origin.** Positions are relative to the top-left corner of the source, which is the top-left corner of the canvas (the first frame's size). For a display it is the monitor bounds from `GetMonitorInfoW`; for a window, the DWM extended frame bounds, re-read on every sample because the window can move. `WindowFromPoint` records whether the pointer was over the source window or something covering it. A pointer on another monitor is outside the source; a minimized or closed window, or the secure desktop (UAC, lock screen), is a gap.

**File.** Each take writes `cursor.jsonl` in its take folder: a header line (`{"format":"cuereview-cursor","version":1,"source":"window","canvasWidth":…,"canvasHeight":…,"sampleHz":60}`), then delta-encoded integer arrays: `[dt, dx, dy]` for a move, `[dt, dx, dy, state]` when the button/outside state changes, `[dt]` for a gap. A line is written on every change and at least every 250 ms. The file is append-only and flushed about once a second, so a crash loses at most the last second; readers stop at the first unparsable line. `capture-timing.json` records the canvas size and `cursorLines` or `cursorError`.

**Touch on Android.** `android:<serial>` recordings write touches into the same file, on every platform (`src-tauri/src/touch.rs`). scrcpy runs with `--no-control`, so the host pointer never reaches the device; instead a reader thread starts with the capture, beside scrcpy, and is stopped and joined first, like the sampler. It starts `adb shell getevent -lt` (no root) on every input device at once, then one `adb shell` probe reads the product model, `getevent -lp` and the display rotation. A pump thread stamps each line as it is read and queues it until the touchscreens and the canvas are known (the canvas once scrcpy has decoded its first frame), so a tap made right after Record, even before the first frame, is kept. The track is flushed about once a second. The stop kills the `getevent` client, which also ends `getevent` on the device, and any probe still running, so it never waits for one. A `getevent` that cannot open a touchscreen (stderr) or ends before the take does (the device went away) gives the take a `cursorError`; what it wrote stays. Meta Quest is skipped: its controllers and hand tracking are not Android input devices. Touchscreens are the devices with `ABS_MT_POSITION_X`/`Y` and `ABS_MT_SLOT` (multitouch protocol B), except touchpads (`INPUT_PROP_POINTER`), narrowed to the `INPUT_PROP_DIRECT` ones when any has it; the emulator's panels have no properties and come one per display, so several are read and the first to touch owns the track until it lifts. A contact whose tool type is `MT_TOOL_PALM` does not touch, as InputReader cancels palm pointers; one that turns into a finger touches down then. The Pixel 8 flags some deliberate taps near its corners as palms throughout, and Android ignores those too. Only the primary contact is written: the finger that touched down while no other finger was down. Fingers added to it, and the rest of the gesture once it lifts, are ignored. That keeps the file at version 1, so `cue` 0.2.0 reads device takes too. A touch-down is a sample with no buttons and a `LEFT` sample at the same place and time, so every touch is a press; moves are `LEFT` samples; a lift, or `SYN_DROPPED`, is a release at the last place and a gap, since touch has no hover position. A resting finger gets heartbeats. The header's `source` is `"device"`.

**Touch mapping.** A raw position becomes the pixel center of its raw step as a fraction of the axis range (`max - min + 1` steps, as InputReader scales a panel onto its display), then is rotated by display 0's rotation, as InputReader applies it: `orientation=` on the display-0 viewport line of `dumpsys input` (Android 9+), else `SurfaceOrientation:` (older). The rotation is read at the start, then again at a touch-down at least a second after the last read. The rotated fraction of the canvas is the canvas pixel. The canvas is the first decoded scrcpy texture (`INFO: Texture: WxH`, the recorded frame size, now also written to `capture-timing.json` for device takes). scrcpy scales the whole display into a video rounded to multiples of 8, so fractions carry over. A rotation that keeps the canvas's shape maps exactly. After a portrait/landscape rotation the frames have the canvas's size turned on its side, and `finalize` letterboxes them onto the canvas (see device capture above), so the rotated fraction is placed in that letterbox instead: `capture::letterbox` computes it for both. Whether the current shape differs comes from the rotation against the one read at the start.

**Touch clock.** `getevent -t` stamps each event with the device clock. The reader adds the smallest receive-minus-stamp difference among the frames of the last 20–30 s (three 10 s periods of host time; the frame that crossed adb fastest), so samples keep the device's own spacing whatever adb buffering does. The window follows a device clock that drifts against the host's either way: a minimum kept for the whole take would follow only one that runs fast, and one 50 ppm slow would put times 90 ms early after 30 minutes. `capture-timing.json` records `touchDelayMs` (`frames`, `p50`, `p95`, `max`): how much later than that fastest frame the others reached the reader. Lines are stamped by the pump as they are read, so the reader's rotation reads delay nothing. The video runs behind the device by scrcpy's capture, encode, transfer and decode time, because its first decoded frame anchors the video at `videoHostStartMs`. A frame exported at a touch's `tMs` therefore shows the screen just before the finger landed. Android's "Show taps" dot appeared in the 30 fps video a median 99 ms (77–128 ms) after the touch's `tMs` on a Pixel 8, and 89–128 ms on the Android 15 emulator (that includes drawing the dot); `touchDelayMs` was 4.0 and 0.4 ms at the median.

**Queries.** `cursor::load` stitches every take's track onto the session timeline with its offset and ends each take with a gap. It reads each take from the folder its index names, never from `Take.folder`. `at(t)` returns the nearest earlier sample unless it is a gap or older than 750 ms; `clicks` lists presses. `x`/`y` are fractions of the canvas measured at the pixel center; `px`/`py` scale them to the session video, which is take 1's canvas rounded down to even sizes; `inVideo` is false outside the canvas or when the pointer was not over the source. The CLI attaches `cursor` to transcript words and segments (`--json`), `find`, `frame`, `frames` and `moments`, and `--mark-cursor` draws a ring on exported PNGs. JSON output only gains fields, so older consumers keep working.

**Limits.** Polling can miss clicks shorter than about 16 ms. `px`/`py` of a take with its own video are its own video's pixels; a take joined into take 1's video by an earlier CueReview, at a different canvas size, is mapped through its `normalize` scale and padding, and `in_video` is false inside the padding. FFmpeg rounds the scaled size to even pixels, so the non-limiting axis can be off by less than a pixel. Touch: evdev sends only changed values and `getevent -lp` reports 0 for multitouch axes, so a slot's position is unknown until both axes have been reported once in the take, and a first touch that lands exactly on the slot's previous raw x or y is not written. `SYN_DROPPED` releases the press, starts a gap and forgets every contact, so a finger already down is not followed until it touches again. Only touches before `getevent` itself is running (an adb round trip after Record) are missed. A touch within a second of a rotation can use the previous rotation. The panel's natural orientation is assumed to match the display's, which an IDC `touch.orientation` would break. Extra fingers are not recorded. Quest, macOS and Linux desktops, and cameras have no track, and `load` returns nothing. The module notes in `cursor.rs` describe what macOS (`CGEventGetLocation` and display bounds) and Linux X11 (`XQueryPointer`) would need; Wayland exposes no global pointer position outside the screencast portal.

## Local transcription

Convert the transcription input to mono, 16 kHz signed 16-bit PCM WAV. Run the local `whisper-cli` with a locally stored model and full JSON output, held to one language per take, or per track of a take with two (`-l <code>`): the language chosen in Settings, or under Auto the one detected for it.

**Two tracks.** A take folder that holds both `mic.wav` and `system.wav` (`transcribe::two_tracks`) is transcribed from each, while it records and in every whole-take pass (Stop, Retry, `cue transcribe`, the refining pass), whenever it was recorded; any other take is transcribed from one file and carries no track. A whole-take pass (`transcribe::transcribe_media_in`: Stop, Retry, `cue transcribe` and the refining pass alike) transcribes the two tracks at the same time, on two threads (`Pass::run_both`), each with its own stretches, its own detected language and its own raw output (`whisper-system.json`; `whisper.json` is the microphone's, as it is a single file's). Neither pass needs the other's: the microphone's echo is recognised by the system track's audio, which its pass converts for itself, so what remains after Stop takes as long as the slower track, not both. Every scratch file is named for its track (`transcribe::scratch`): the system track's speech files start with `system-`, and so do the files made of them (`system-speech.wav`, `system-stretch.wav`, `system-transcode.log`, `system-vad.txt`, `system-vad.log`, `system-language.wav`, `system-language.log`, `system-transcription.log`), while the microphone's keep the names a single file's have. Each pass runs Whisper with the final thread count from 8 logical threads on (4 each there, 8 each from 16) and with half the logical threads below that (`transcribe::track_threads`), so the two never ask for more threads than a processor with two or more has, each keeping at least one. The result is that of one pass after the other. When a track fails, the take fails with that track's error and the other track's tools are stopped (the passes share one stop flag, which is the refinement's cancel flag when there is one, so cancelling stops both); when both fail, the system track's error is the take's. The callers hold the inference lock around the whole pass, as for one track. `transcribe::merge_tracks` then sets `track` (`microphone` or `system`) on every segment, orders the rows of both by the time the app shows for a row (its first word's alignment point, else its start: Whisper starts a segment where the one before it ended, which can be long before its words), the system row first where two share it, and numbers them anew. `trackLanguages` on the transcript and on a take mark holds each track's `language` and `languageDetected`; `language` beside it is the microphone's, or the system's when the microphone has no words, for readers that know one language per take.

**The echo gate** (`echo.rs`). The loudspeakers reach the microphone 80 to 176 ms late, about 20 dB below the system track and only about 7 dB below the reviewer's voice, so a call would be written twice. Before the microphone's speech is looked for, detected or transcribed, each of its speech regions (the Silero detector's, padded by 100 ms) is compared with the system audio of the same span, both at 16 kHz: the share of the region's 300 to 3400 Hz power that the system audio explains linearly, which is the magnitude-squared coherence of the two weighted by the microphone's power per frequency bin, from Welch segments of 64 ms (`rustfft`), after the system audio is shifted by the delay, searched from the microphone 50 ms ahead to 500 ms behind, at which the two correlate most in that band. A region is echo when the system audio is above -45 dBFS in the span and the share is 0.4 or more (`echo::ECHO_SHARE`, `echo::ACTIVE_DBFS`). A region shorter than 1 s is scored on 1.5 s around it, one longer than 15 s in equal pieces of at most 15 s, and audio too short for eight Welch segments is never echo. Echo is zeroed in the 16 kHz copy handed to the detector, to language detection and to Whisper (`echo::silence_echo`), so the copy keeps its length and every other sample, the take's own `mic.wav` is untouched, and nothing is transcribed there; what Whisper makes up over the zeroed audio is left out afterwards (`transcribe::heard_rows`, below). A region with the reviewer's words and echo together scores lower and is kept whole. On the 2 h 31 min recording the rule was set on, 1.2 % of 1005 echo regions stayed in, none of the reviewer's 275 was lost by ear, and with the system audio taken from another moment, as on headphones, 0.6 % of the microphone's regions were dropped. In a release build it takes about 0.08 s per minute of microphone speech on the reference PC.

**The take's language.** `settings.json` `language` is one of the speech model's 99 codes (`settings::LANGUAGES`: whisper.cpp's `g_lang` at revision `d1be6fde` without Cantonese, which the base and small models have no token for; the table `get_languages` serves to Settings) or absent, which is Auto; a code the table does not hold reads as Auto. A chosen language holds every take and nothing is detected. Under Auto each take is detected on its own:

- **Detection** (`transcribe::detect_language`) runs `whisper-cli -m ggml-base.bin -f <16 kHz speech> -dl -ng`, which hears the first 30 s of the file and exits, and reads `auto-detected language: xx (p = n)` from its log (`language.log`). Base is multilingual and always installed, so detection never waits for a download. A missing line, a failed run or a code outside the table is no guess, never a failure of the take.
- **Deciding** (`stretches.rs`). A guess with p >= 0.9 (`stretches::CONFIDENT`) decides the take, and the take is held to that language from then on, whatever later speech sounds like. Without a confident guess the take gets the language with the largest summed probability over its guesses (`stretches::likeliest`), and English when nothing was guessed at all.
- **While recording**, each finished stretch is detected until one decides. Before that a stretch is transcribed in its own guess and kept as provisional with the guess; once the take is decided, the provisional stretches made in another language are transcribed again, each from a copy of the take's audio from its start (`transcribe::redo_provisional`), before newer stretches are handled; a copy that cannot be made is tried again at the next update, and a stretch whose transcription fails is left to Stop. The guess of the words still being heard uses `-l auto` until the decision and the take's language after it. A take that stops undecided is settled by Stop the same way (`Stretches::settle`), and Stop redoes its stretches in another language.
- **A whole-take pass** without stretches (Stop without usable ones, Retry, `cue transcribe`) detects first (`transcribe::detect_take_language`): up to three windows of 30 s of speech-only audio, cut by the speech regions the pass already has from the detector, so a quiet or noisy start decides nothing. The first window with a confident guess decides, otherwise the largest sum. The background pass that refines a take made from stretches keeps the language, and whether it was detected, that Stop saved with them, whatever Settings say by then, and does not detect again.

Each track of a take with two is detected, decided and held in the same way, on its own: its stretches carry its decision, and a whole-take pass detects it from its own speech, the microphone's after the echo is silenced.

`transcript.json` carries `language` and, when Auto found it, `languageDetected`; a session with takes carries both on each take mark as well (`takes::merge_take`), and its own `language` is its first take's. `trackLanguages` travels with them, on the transcript and on the mark of each take transcribed from two tracks. The live transcript in the recording status names the language once the take is held to one, and in `trackLanguages` what each track has decided so far. A take, or a track, without words has no language.

**Models.** `deps.rs` pins four models from one Hugging Face revision of ggerganov/whisper.cpp, each with its exact size and SHA-256: `base` (148 MB, installed by Install transcription), `small.en` for English and the multilingual `small` for every other language (488 MB each), and `large-v3-turbo` (1,624,555,275 bytes, alignment preset `large.v3.turbo`), which runs only on a graphics card (**The device**, below). A final transcription on the processor uses its take's language's small model once it is installed (`deps::final_model`), else `base`, held to the same language. While recording, finished stretches use the same model, chosen per language when the take starts (`deps::TakeModels`), and the guesses of the words still being heard use `base`, which is about twice as fast per update (see the live transcription below). Each runs with its own alignment preset. A language choice needs its own model, and Auto needs both small models (`deps::needed_models`); with Large chosen the larger model comes after them (`deps::wanted_models`). Whenever `base` is installed and a needed model is not, the app downloads the missing ones on a background thread, in order, the English one first and the larger one last: at start, after Install transcription, when a saved language or model changes, and on Try again (`download_language_models`, refused with its reason before Install transcription). One download runs at a time; when the choice changes during one that the new choice has no use for, it stops and what the new choice needs follows; choosing Standard leaves an installed larger model in place. The download streams into `<file>.download` and is renamed only when its size and SHA-256 match; any failure removes the partial file, partial files a closed app left are removed when the next download starts, `cue setup` reports a download another process is writing (its partial file grew in the last 30 s) as `downloading`, and the state is reported as `languageModels`, one entry per needed model in download order but the larger model first, by `get_setup_status` and by the light `get_language_models` that Settings polls, each poll after the previous reply (`ready`, `downloading` with the bytes received, `failed` with a plain sentence, or `missing`). `cue setup --install` downloads them in the foreground. `CUEREVIEW_MODEL` replaces every model, detection's included, with `CUEREVIEW_DTW_MODEL` naming its alignment preset; `languageModels` is then left out.

**The device.** On Windows x64 the runtime folder also holds a Vulkan build of `whisper-cli` in its `vulkan` subfolder and whisper.cpp's `samples/jfk.wav` (11 s of speech); where the Vulkan build is missing (`deps::card_build`), as on macOS, Linux or with the downloaded runtime, nothing is measured and the processor builds transcribe exactly as without it.

- **Measuring** (`deps::measure_devices`, on its own thread from `spawn_measure` in `lib.rs`, under the inference lock and only while nothing records): the sample, `jfk.wav` played twice back to back (22 s, as long as a stretch, so loading the model, 1.6 GB for the larger one, does not decide the time; the app writes it anew for each measurement to `<root>/speech-sample.wav`, removed after it, from the shipped file's PCM, which must be 16 kHz mono 16-bit, else nothing is measured), through `small`, else `small.en` (a computer held to English has only that one; both are the same size, and the sample is English), else `base`, held to English with a final transcription's options but no vocabulary or output files, twice on the processor build (`-ng`, the threads of a whole-take pass) and twice on each card the Vulkan build lists in its first run's log (`ggml_vulkan: N = <name> (<driver>) | …`; the name drops the last bracketed group), with `-dev N` and four threads. The second run counts, so a card's one-time warm-up (16 s on the reference PC) does not; a card counts only when the log of each of its runs reads `whisper_backend_init_gpu: using VulkanN backend`, because a run that cannot use its card falls back to the processor in the same process and exits with 0; a run still going after 180 s fails. The fastest card that beat the processor is chosen; a tie goes to the processor. A Vulkan build that does not start (no Vulkan loader) lists no card.
- **The saved result** is `<root>/speech-device.json`: the computer it was made on (`computer`: the app's version, the folder and file name, size and write time of each `whisper-cli` build timed, without its full path, because the app finds the bundled runtime through a verbatim resource path (`\\?\C:\…`) and `cue` beside its own executable, and the display adapters with their driver versions, `DriverDesc` and `DriverVersion` of each `00NN` key under the registry's display class `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-e325-11ce-bfc1-08002be10318}`), the `sample` (`jfk.wav twice`), the `model`, `processorMs`, each card's `index`, `name` and counted `ms`, the `chosen` card, `stopped`, and `large`. The app measures at start, after Install transcription and after a download ends, when that is due: nothing saved, a saved result from another computer than this one is now or made on another sample, one made with base once a small model is installed (as on a fresh install, which measures before the small models are downloaded; one made with `small.en` is not made again when `small` arrives, nor the other way round), or the larger model waiting to be timed; and on "Test the graphics card again" (`test_speech_devices`, refused while a recording runs). A recording that starts, or a transcription that wants the inference lock (a live update, the pass after Stop, Retry, the refinement: `lock_inference` in `lib.rs`), kills the run in progress and saves nothing, so no transcription waits for a measurement; it runs again at the next idle moment, when the pass refining a transcript after Stop has ended.
- **Where a run goes** (`deps::Facts::card`): to the chosen card when the Vulkan build is there, `settings.json` `graphicsCard` is not `false`, the saved result was made on this computer as it is, the card has not stopped and no measurement is queued or running; otherwise to the processor build. Stretches and their redo while recording, the pass after Stop, Retry, `cue transcribe` and the refining pass go there (`transcribe::run_final`), each run choosing anew, so the switch takes effect while recording and both tracks of a take with two run on the card at the same time. A run on the card is the Vulkan build with `-dev N` instead of `-ng` (`settings::decoding_args_on`) and four threads (`settings::CARD_THREADS`). Language detection, the grey live guess, the vocabulary's token probe and the speech detector always run the processor build.
- **A failure** (`transcribe::on_device`): a run on the card that fails to start, crashes, exits with an error or leaves no readable output, and was not cancelled, is done again on the processor build with the small model of its language, and the card is marked `stopped`; a run that ends well but whose log does not show its card in use is kept, and the card is marked the same way. The processor transcribes until the next measurement, which clears it.
- **The larger model.** A chosen card that ran the sample with `small` or `small.en` in two thirds of the processor's time or less offers it (`largeOffered`; a measurement made with base offers nothing), for every language, English included: on the RTX 5090 large-v3-turbo took 1.5 times the small model's time. With `settings.json` `model: "large"` it is downloaded after the small models; once installed it is timed on the card, twice with the second counted (`large`), then twice at the same time, as the two tracks of a take run. If it is slower than the processor with the small model, or any of those runs fails or shows the processor, it does not fit (`large` is `failed`): the small models go on (`largeSlow`) and the card is not stopped, since they run there. A final run uses it only when it is chosen, installed, offered, not slow and the run is on the card (`deps::Facts::large`), held to the take's language, for every language; a take chooses it when it starts (`deps::TakeModels`). Otherwise, and for the repeat on the processor, the small models transcribe. Choosing Standard goes back to them and leaves the file in place.
- **Reporting**: `SetupStatus.speechDevice` (`state` `measuring` or `ready`, `kind` `graphicsCard` or `processor`, the card's `name` when it transcribes, `card` with `name` and `stopped` for the chosen card even while the switch is off, `largeOffered`, `largeSlow`, `largeInUse` when the larger model transcribes final runs now (`deps::Facts::large`), and `measurable`, whether the runtime has the Vulkan build to measure; the card and the offer come from a measurement of this computer as it is, or the last one while measuring, and a stale one reports none), from `get_setup_status`, the light `get_speech_device` that Settings polls while measuring, and `test_speech_devices`, which is refused without the Vulkan build. `cue setup` reads the saved result and never measures; without one it reports the processor.

Before inference, the bundled `whisper-vad-speech-segments` executable checks the entire input with a pinned Silero v6.2.0 model. A valid zero-region result produces an empty transcript. Any detected speech passes the original, unchanged PCM to Whisper, preserving its playback clock. Detector errors or malformed output remain failures with diagnostics, never silent success. This whole-input gate suppresses the tested noise-only hallucinations; it does not remove noise from mixed speech/noise recordings. After every final Whisper run, `transcribe::heard_rows` leaves out each row of which less than a tenth lies within 1 s (`HEARD_SLACK_MS`) of the speech regions of the same audio, and a row of no length that lies outside them, because Whisper writes rows over silence, over the microphone's zeroed echo above all, and large-v3-turbo far more than small. A row is measured from its first word's alignment point (`agent::segment_seek_ms`), else its start, to its end, since Whisper starts a row where the one before it ended; the widened regions are joined first so no time counts twice. The regions are the whole-take pass's (the detector's, padded by 500 ms) for the audio after Stop's stretches, Retry, `cue transcribe` and the refining pass; a live stretch's own regions after the echo is silenced (`live_commit`, padded by 100 ms), since a stretch can hold most of 30 s without speech; and those detected again for a stretch transcribed again (`redo_stretch`, and Stop's `to_redo`). The raw JSON keeps every row. The detector can also miss speech.

Whisper token timestamps are estimates. Retain the original JSON. Construct display words by joining continuation tokens and punctuation, excluding model control tokens. Never manufacture word timings by evenly dividing a sentence. Store all UI/CLI offsets in milliseconds from the playback origin; seek only within the available media duration. Silence between words must clear the active-word highlight.

Leading silence can substantially distort the first word's estimated interval: a ten-second delayed fixture placed its first word near zero while later words retained their original clock. The installed models therefore enable DTW with flash attention disabled. Its token alignment points populate optional word `seekMs` fields, preserving raw `startMs`/`endMs`. Word and sentence clicks and phrase-based frame extraction prefer these points. Highlighting uses a short visual pulse near an alignment point, not a fabricated spoken interval; old transcripts retain interval highlighting. Live updates shift alignment points onto the session clock and bound them to the snapshot. Custom models require an explicit compatible `CUEREVIEW_DTW_MODEL` preset to enable this path.

Alignment increased the measured two-thread inference time from roughly 2.2 to 4.0 seconds. It supplies estimated points, not corrected spoken durations. Direct Whisper VAD transcription altered the tested token clock, so the detector remains a whole-input gate and recognition receives the original PCM unchanged.

Transcription failure must preserve playable recorded media and offer retry. An empty result from silent audio is a valid empty transcript, not a fabricated paragraph.

During recording, a background worker (`live_transcription` in `lib.rs`) copies a live audio track of the take from the end of its last finished stretch, at most 60 s, about every second (`ActiveCapture::snapshot_audio_from`, which takes the track; `audio_tracks` names those being recorded). It converts the copy to 16 kHz, finds its speech with the Silero detector padded by 100 ms (`transcribe::speech_regions`), and guesses its words with base, one beam and no alignment points (`transcribe::live_guess`), which it shows at once. Then it finishes stretches (`transcribe::live_commit`, `stretches.rs`): once 28 s wait, a stretch ends 300 ms into the last pause of at least 600 ms between 10 and 30 s, or in the middle of the longest gap of at least 200 ms past 30 s, the silence before the first word included; a cut in that silence, and 28 s without speech but their last second, are skipped untranscribed. Each finished stretch is transcribed once in the take's language with that language's model, and saved in the take folder as `stretches/stretches.json`, version 2 (the audio file, the take's language once it is held to one and whether it was detected, where the stretches end, their take-relative words, and per stretch its bounds, language, model, guess and whether it is provisional) beside each stretch's raw Whisper output. The live transcript is the stretches' words, then the guessed words as one segment whose id starts with `live-`, all on the session timeline. Whisper works in the take's `live` scratch folder, outside the capture/state lock and under the shared inference lock. Results publish only for the still-active session, and stopping cancels the live subprocess.

A take recording a microphone and system audio has one stretch state per track, saved as `stretches/system.json` and `stretches/microphone.json` (each names its `track`; raw output `<track>-<start>.json`). Every cycle serves the system track first, then the microphone (`stretches::turns`), each turn under the inference lock. The microphone's turn also copies the system track over the same span, and the echo gate silences the microphone's copy against it before anything is guessed or cut into stretches; a stretch transcribed again after the language decision is silenced the same way. A live track has no samples until its device delivers the first packet, and a loopback delivers none while nothing plays, so the system track can be empty, or end long before the microphone's, for as long as the computer is quiet. A track of two that cannot be copied, for that or any other reason, is silent for the cycle and the other one is served as usual; only when no track could be copied, or a transcription fails, does the cycle show an error (`stretches::copy_for`, `stretches::cycle_error`). The microphone is compared with the system copy only when that copy was made, holds audio and starts where the microphone's does (`stretches::is_reference`). Each copy starts at the last sample at or before the point asked for and reports its start in whole ms rounded down, so two devices at different rates (a 48 kHz microphone and a 44.1 kHz loopback from 12345 ms: 12345 and 12344) report starts up to 1 ms apart for the same point, which is the tolerance (`stretches::SAME_START_MS`); their audio starts less than one sample period of the slower track apart. Neither that nor the sample that FFmpeg's seek leaves between two tracks converted from one offset after Stop is assumed to be zero: it is part of the delay the echo gate searches for. Where the system copy ends earlier, the system audio counts as silent from there, as the finished track is, so a region past its end is never echo and one across it is judged whole. Without a system copy nothing counts as echo and the microphone's turn is that of a take with one track. At Stop a track that never got a sample is silence of the take's length, and one left without a sample has no speech, so neither fails the take nor costs the other track its stretches. The two live tracks are compared before the take's final resampling, so clocks that have drifted apart by more than the delay search covers leave echo in until the pass after Stop. The microphone's words still being heard are guessed in every cycle, the system track's in every second one, its last guess showing meanwhile, so base runs three times in two seconds, not four. The live transcript (`stretches::live_of_tracks`) holds the finished rows of both tracks merged as after Stop, each with its `track` and an id of its track (`stretch-system-…`), then at most one segment of words still being heard per track (`live-system-…`, `live-microphone-…`).

At Stop, `transcribe_media` reuses saved stretches (`stretches::usable`), for each track of a take with two, when they were cut from the audio file it reads (`mic.wav`, or `system.wav` for a take without a microphone, read instead of `audio.wav`), were made under the language choice that holds now, and those in the take's language were made by the model that language uses now; a file of version 1 is not reused, and one track's stretches that cannot be used are forgotten without the other's. It transcribes again the stretches made in another language, then only the audio after the stretches, the microphone's through the echo gate both times, and saves the take's language with them for the refining pass. The take's transcript is then ready about 3 s after Stop on the reference PC, whatever its length. Retry and `cue transcribe` forget the stretches first (`stretches::forget_session`), so they transcribe the whole take. Because stretches make more word errors than a whole-take pass (about 4 points on a five-minute review), the app then refines each take made from stretches in the background (`spawn_refine`, `transcribe::refine`): it transcribes the take whole, cancellable, replaces its words, forgets the stretches and raises `transcriptRevision` in the recording status, after which the app reads the open transcript again. Any recording starting stops every refinement (Whisper beside a capture runs only with the live threads); Retry or a delete stops that recording's, and a delete waits for a refinement it stopped to end. The transcript from Stop then stays, and a refinement cut short is not resumed.

Live snapshots use the PC microphone and Windows loopback, whichever the take records. Android device audio by itself has no local PCM snapshot track and is transcribed after stopping; selecting a PC microphone enables progressive commentary for device reviews.

## Settings and decoding policy

App-wide preferences live in `<root>/settings.json` (`src-tauri/src/settings.rs`), shared by the app (`get_settings`/`save_settings`) and the CLI. Saving validates, normalizes and writes the file atomically; a missing or unreadable file falls back to the defaults, so it never blocks recording or transcription. Every field is optional, so older and newer files stay readable.

`settings::decoding_args` builds the Whisper options for every final and live transcription: `-l <code>`, the language of that run, which its caller passes ([the take's language](#local-transcription); `auto` for the live guess of an undecided take), `-ojf -ng` (`-ojf -dev N` for a run on graphics card N), then `-nf -nth 0.3` so noise is not retried at higher temperatures. Without a vocabulary it passes `-mc 0`, which carries no decoded text into later 30-second windows and avoids repeating a hallucination across them.

The vocabulary is off by default. It accepts at most 20 terms separated by commas or new lines, 200 characters joined with ", ", and an estimated 75 prompt tokens, in printable ASCII only (on Windows, `whisper-cli` reads its arguments in the ANSI code page). The Settings dialog applies the same rules before saving, and the backend validates again. When it is set, the args become `-mc <prompt tokens + 1> --prompt "<terms>" --carry-initial-prompt`: the prompt is repeated in every window, and the context budget leaves no room for decoded text, which keeps the `-mc 0` behavior otherwise. The exact token count comes from the model's own tokenizer, by a short `whisper-cli` probe that stops before the encoder runs, cached per process. A failed probe is cached too, and a probe still running after 20 s is killed, because it can run while the inference lock is held; only a missing model is not cached, so installing it takes effect at once. A prompt whose real count exceeds 96 tokens, or whose count cannot be measured (for example, no model yet), is not used, and decoding stays as without it. Measurements behind these limits are in the module notes: even 23 carried tokens let a hallucination repeat across a noisy recording, and prompts of 130 tokens or more invented lists on noise.

## Agent CLI

`cue` is a thin binary (`src-tauri/src/bin/cue.rs`) over the library:

- `cli.rs` is pure: the argument parser, per-command help and the plain-text formatters (`--segments`, clocks). `cargo test --lib` covers it. `cue.rs` is one call to `cli::dispatch`, which parses first; `--help`, `-h` and `help COMMAND` print and exit 0 before the store is opened or a lock is taken, and an unknown option or a missing value is an error that points at the command's help. It then opens the store, takes the process lock when the command needs it and runs the command while holding it.
- `agent.rs` holds the handoff text (Copy for agent), phrase search, frame and batch-frame export, clips and moments. Every time is a session time: a frame is taken from the take video it falls in (`takes::video_at`), at that video's size, and a clip from one take video; a clip whose range crosses into the next take's video is refused, naming the take it starts in and where that video starts. Frames are scaled down with `--max-width` and never up, written to new files only, and an invalid batch writes nothing; when one frame of a batch fails, the frames it already wrote are deleted. `--output` and `--output-dir` must be local paths: URLs and FFmpeg protocols (`pipe:1`, `tcp://…`) are refused, and FFmpeg gets every output as an absolute `file:` path, so a name starting with `-` is never read as an option. `moments` matches pointing words ("here", "there", "this", "these", "that", "those", "see", "look at", "right here", "over here"), skipping "that" as a conjunction and "there is", and adds the cursor and the clicks within 1 s of each moment.
- Only `record`, `transcribe`, `discard-take` and `setup --install` hold the data folder's process lock (`.instance.lock`), which the desktop app holds while it runs. Everything else, `rename` included, runs beside the app. Every write to a session (app or CLI) takes that session's lock in `<root>/locks/<id>.lock` and re-reads `session.json` before changing it; the lock files live outside the session folders so deleting a recording never races its own lock. The app refreshes the sidebar when its window regains focus, which picks up a CLI rename.
- Output is JSON on stdout and errors on stderr with a nonzero exit. Session, transcript and evidence output only ever gains fields (`takes`, `cursor`, `width`/`height`, `formatVersion`, `videos`, `languageDetected`, each take's `language`, a segment's `track`, `trackLanguages`), so existing consumers keep working. The two text formats of `cue transcript` (`cli::format_text`, `cli::format_segments`) put `mic: ` or `system: ` before the text of a row that has a track, and print every other row as before.

## Persistence and process ownership

Each session groups its metadata, final video, transcript, takes and evidence exports. Persist state transitions so a restart can identify interrupted recording or processing work. Write metadata atomically. Validate identifiers and resolve paths under the configured data directory. The agent interface should report errors on stderr and machine-readable results on stdout.

The sidebar presents optional collapsible sections and ungrouped Recents in one list, without project tabs or a recording-header category picker. Sections reuse the existing project metadata and IDs. New recordings have `projectId: null`; dragging into a section or using Move to section changes only that field, leaving the session directory unchanged. Dropping back into Recents clears it. Section expansion is remembered locally, and unknown section IDs fall back to Recents so recordings remain reachable. The title bar search filters sessions by name only. WebView native file-drop interception is disabled to support HTML drag-and-drop on Windows. Unnamed recordings carry `autoTitle: true` and receive a short title from the first nonempty transcript phrase. An explicit rename, in the app or with `cue rename`, clears that flag. Legacy sessions default to manual titles and retain their existing project IDs, requiring no destructive migration.

Section order is saved atomically in section-order.json. Deleting a section first clears each member recording's projectId, then removes the section metadata. Deleting a recording validates the physical UUID directory under the configured sessions root, rejects linked/reparse paths, and removes its payload before session.json so a locked-file failure remains retryable. UI confirmation identifies the recording and the selected video is unloaded before deleting its files. Runtime ownership guards serialize these operations against capture/transcription start; partial section failures refresh sidebar membership.

Markers left the UI in v0.2.0. The store functions, the `get_markers`/`add_marker` commands and `markers.json` remain for one release so legacy data stays readable; they are deprecated, and the CLI has no marker commands.

Launch dependencies with argument arrays rather than shell-generated command strings. Retain process handles, capture diagnostic output, stop recorders gracefully, and check exit status and output validity before declaring success. Killing an encoder may leave an unfinished container; intermediate recordings and logs should be retained for recovery.

## Dependency setup

Development requires Node.js, the Rust MSVC toolchain, Visual Studio C++ build tools, a Windows SDK, and WebView2. Runtime media work needs FFmpeg/ffprobe and whisper.cpp plus a model. Device capture additionally needs scrcpy and ADB. Pin dependency versions and document their source and license when bundling. Install or download tools into an application-controlled directory; a developer's PATH must not be the only working configuration in a packaged build.

Tools are found in this order: the downloaded runtime in `<root>/tools/whisper-b5454`, `<root>/tools`, the runtime bundled next to the app (`tools/whisper-b5454` in the resource folder or beside the executable), PATH, and on macOS/Linux the standard Homebrew and system binary folders.

The bundled speech runtime is built twice on Windows and Linux x64 (`scripts/build-speech-runtime.mjs`): a plain build that needs only SSE4.2 (the script turns ggml's BMI2 default off), and a build for AVX2, FMA, F16C and BMI2 in the folder's `avx2` subfolder. On Windows x64 a third, the Vulkan build of `whisper-cli` in the `vulkan` subfolder, runs on a graphics card ([Local transcription](#local-transcription)). Wherever `whisper-cli` or `whisper-vad-speech-segments` is found, `deps::tool` runs the `avx2` build beside it when the processor has all four; the plain build is about eight times slower. A final transcription uses half the logical threads, at most 8 and at least 4 where there are that many; a live update uses a quarter, at most 4 and at least 2 where there are that many, beside the capture and its encoder.

Setup checks should distinguish missing executables, missing models, unavailable microphone/output endpoints, and unauthorized/disconnected devices. Only capabilities affected by a missing optional device dependency should be unavailable.
